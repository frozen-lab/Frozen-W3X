# 《生化狂潮_迁移版V2.w3x》崩溃风险深度排查报告

针对地图在实机运行中可能发生的闪退（Crash）、无响应卡死、联机不同步（Desync）问题，我们对解包后的 `war3map.j`（45,098 行 JASS 脚本）及资源归档进行了静态分析与代码模式审查。

---

## 核心崩溃风险排查汇总

| 风险等级 | 问题类型 | 触发位置 / 关键代码 | 诱发后果 |
| :---: | :--- | :--- | :--- |
| **FATAL (致命)** | **循环变量混淆导致空指针越界** | `war3map.j` L8090, L8297, L8506 | 游戏在开局或玩家变成母体时**瞬发闪退/致命错误** |
| **CRITICAL (严重)** | **平台私有 API (DzAPI) 运行时缺失** | `war3map.j` L1221 (`DzSetUnitModel`) | 在原版单机、局域网或不支持的平台**直接闪退** |

## 详细排查与代码证据

### 1. 致命缺陷：外层 `ydul_i` 循环中误用 `GetForLoopIndexA()`

在 `war3map.j` 中处理**母体感染与阵营关系设置**的逻辑函数（如 `Trig_ordinaryFunc003`）中，存在严重的循环变量混淆：

#### 现场代码展示（以 L8083 ~ L8097 为例）：
```jass
8083:   set ydul_i = 1
8084:   loop
8085:       exitwhen ydul_i > 12
8086:       if((kx_N1b5oZ[GetConvertedPlayerId(ConvertedPlayer(ydul_i))]==1))then
8087:           call SetPlayerAllianceStateBJ(..., ConvertedPlayer(ydul_i), ...)
8088:       else
8089:           // 错误致命行：此循环由 ydul_i 驱动，并没有使用 bj_forLoopAIndex！
8090:           if((LoadBoolean(YDHT,GetHandleId(ConvertedPlayer(GetForLoopIndexA())),0x602978BD)!=true))then
8091:               call SetPlayerAllianceStateBJ(..., ConvertedPlayer(ydul_i), ...)
8092:           endif
8093:       endif
8094:       set ydul_i = ydul_i + 1
8095:   endloop
```

#### 为什么这会导致游戏崩溃？
1. 在进入 `ydul_i` 循环之前，上一段逻辑刚刚执行过一个 `forLoopA` 循环（L8024~L8036），此时 `bj_forLoopAIndex` 的残留值是 **13**！
2. 当执行到 L8090 时，`GetForLoopIndexA()` 返回 **13**；
3. `ConvertedPlayer(13)` 的 JASS 实现是 `Player(13 - 1) = Player(12)`；
4. **在魔兽争霸 1.24/1.27 标准对战中，有效玩家索引仅为 `Player(0)` 到 `Player(11)`（共 12 人）**。
5. `GetHandleId(Player(12))` 传给 `LoadBoolean` 时，在某些版本魔兽引擎或极端内存状态下，访问了未初始化的玩家结构体指针，**直接引发 Windows 端 `ACCESS_VIOLATION (0xC0000005)` 致命错误闪退**！
6. 同样的问题原封不动出现在：
   - **Line 8297**
   - **Line 8506**

> **修复建议**：将 L8090、L8297、L8506 的 `ConvertedPlayer(GetForLoopIndexA())` 修改为 `ConvertedPlayer(ydul_i)`！

---

### 2. 严重缺陷：依赖平台私有注入接口 `DzSetUnitModel`

在 `war3map.j` 的皮肤更换系统中：
```jass
1207: native DzSetUnitModel takes unit whichUnit, string path returns nothing
...
1221: call DzSetUnitModel(u, model)
```
地图在 36926~37129 行频繁为单位动态更换皮肤（如 `CS_JNTM.mdl`, `zb_nvyao_3.mdl` 等）。
- **崩溃场景**：
  - 该原生函数属于网易对战平台/KK对战平台的扩展 DLL 钩子。
  - 如果在**原版冰封王座客户端（如 1.24e/1.27a 单机局域网）**或第三方不支持该 native 的魔兽引擎中运行，一旦触发皮肤更换，引擎找不到该原生函数地址，**直接闪退退出**。

---

### 3. 中后期卡死与内存泄漏风险：0.5s 周期装备锁全图扫描

在 L7485~L7547 实现的 `InitTrig_kxEquipLock`：
- 地图启动了一个 **0.50 秒一次的永久定时器** `game_kxEquipLockScan`；
- 每个周期遍历 12 位玩家的所有单位，进行 `CreateGroup` 与 `ForGroup`；
- 加上地图中还有多达 **36 个运行间隔小于 0.05 秒（20Hz+）的高频定时器**；
- 魔兽争霸 3 JASS 虚拟机的 Handle 计数器上限为约几十万，长时间运行若未严格成对 `DestroyGroup` / `DestroyTimer`，会导致 Handle 耗尽卡死。

## 修复排查行动清单 (Action Plan)

若需要让原地图恢复稳定运行，需要执行以下补丁操作：

1. **[必改 P0] 修复 3 处索引越界**：
   - 检索 `war3map.j` 第 8090、8297、8506 行，将 `GetForLoopIndexA()` 替换为当前的循环变量 `ydul_i`。
2. **[兼容 P1] 为 DzAPI 添加单机安全垫 (Fallback Guard)**：
   - 在 `kx_SetSkin` 增加环境检查或空函数兜底，防止原版魔兽加载时因未定义 native 崩溃。
3. **[优化 P2] 重新导出纯净 MPQ**：
   - 补齐丢失的 `(listfile)`，将解出的贴图与模型以标准规范重打包。
